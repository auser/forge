# Forge v0.2 Implementation Prompt

Read `specs/project.md` and `specs/adrs/0001-core-architecture.md` first. Implement a real, compiling v0.2 of Forge; do not produce scaffolding or pseudocode.

## Objectives

- Preserve the v0.1 architecture and CLI.
- Implement `DecisionRouter` with static, mock, and configurable HTTP System One-compatible backends for TypeSafe Jev, Kev, and local variants.
- Implement routing confidence, capability filtering, timeout, fallback, and trace metadata.
- Implement skills with progressive `SKILL.md` loading and execution through `ExecutionProvider`.
- Implement deterministic incremental project graph and graph-aware context selection.
- Implement REST/SSE through the same `AgentService` used by the CLI.
- Add a versioned JSON event protocol.
- Add executable BDD scenarios under `tests/features/`.
- Keep the binary provider-neutral and lightweight.

## Required behavior

Use Clap derive and support `init`, `run`, `serve`, `resume`, `cancel`, `graph`, `skill`, `model`, `config`, `doctor`, and `version`. Implement `-v`, `-vv`, and `-vvv` through `tracing`.

Implement configuration precedence exactly as:

```text
defaults → configuration files → environment variables → CLI flags
```

`forge init` must be idempotent, create `.forge/`, build the graph, and update `.gitignore` without overwriting files or duplicating entries.

All command, file, test, and skill-script execution must pass through `ExecutionProvider`. Implement native and mock providers; keep MVM behind the same trait.

Implement OpenAI-compatible model access for oMLX and compatible servers. Make model capabilities explicit rather than assuming all providers support tools, streaming, structured output, vision, or large context.

Discover skills from project and user directories, load metadata first, activate full instructions only when selected, and record activation in the session log.

Build a deterministic graph without requiring network or model calls. Store it below `.forge/graph/` and support files, symbols, imports, tests, search, and incremental freshness.

Implement REST endpoints for health, capabilities, models, runs, cancellation, events, skills, graph status, and context. Add SSE streaming. Bind to loopback by default. Keep the service boundary transport-neutral so gRPC can be added later.

Use append-only JSONL events for runs and sessions. Do not log secrets.

## BDD requirements

Add executable scenarios for configuration precedence, initialization, graph freshness, skills, routing, fallback, execution providers, REST/SSE, tracing, JSON output, privacy, sessions, cancellation, and approval. Use mock providers so the suite runs offline. Test behavior, not implementation details.

## Verification

Run and report:

```bash
cargo fmt --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-features
forge init
forge graph build
forge graph map
forge skill list
forge serve
curl http://127.0.0.1:7341/health
```

Do not claim completion without running the tests. Finish with changed files, implemented features, BDD scenarios, commands/results, limitations, and the recommended v0.3 work.
